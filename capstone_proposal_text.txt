PROJECT AND TASK DESCRIPTION

(a) Project Summary
--------------------
CAAR-CDSS is a trustworthy clinical decision support system that uses
Adaptive Evidence Budgeting (AEB) — a novel iterative retrieval loop that
expands the evidence budget round-by-round until a calibrated confidence
threshold (θ) is reached, then abstains rather than hallucinating when the
corpus cannot ground the answer.

The system addresses three documented gaps in the 2024–2026 clinical-RAG
literature:
  1. No standardised hallucination-evaluation protocol (every paper measures
     differently, making cross-paper comparison impossible).
  2. Confidence-calibrated abstention is underexplored — most systems always
     answer, even when evidence is insufficient.
  3. Single-specialty scope limits generalizable conclusions.

Core pipeline (already implemented):
  • Hybrid retrieval: dense (BGE-M3) + BM25 fused via Reciprocal Rank Fusion
  • NLI hallucination verifier: DeBERTa-v3-large-MNLI checks each claim
  • Confidence calibration: multi-signal fusion (retriever sufficiency +
    evidence agreement + hallucination penalty) with temperature scaling
  • Risk-aware triage: hard emergency escalation + soft escalation when
    evidence budget is exhausted
  • FastAPI backend, React frontend, MockReasoner for GPU-free testing

Generation LLM: microsoft/Llama3-Med-8B-Instruct (medical-tuned, Llama 3
Community License — research-clear).

Corpus: epfl-llm/guidelines (48,096 clinical practice guideline articles,
HuggingFace), spanning multiple clinical specialties (general medical decision support).

Evaluation benchmarks: MedQA (primary), PubMedQA (secondary).
Evaluation framework: RAGAS (Faithfulness, Answer Relevancy, Context
Precision, Context Recall) + custom abstention-rate curve sweep.

REALISTIC CONSTRAINTS

1. Hardware: RTX 4050 with 6 GB VRAM — below all standard LLM serving configs.
   Mitigation: 4-bit NF4 quantization for local dev (~4.5 GB active VRAM);
   Kaggle T4 (16 GB, free 30h/week) for paper experiments.

2. Cost: zero API budget for generation or judging.
   Mitigation: fully open-source model (Llama3-Med-8B); HF Inference API
   free tier for RAGAS judge (~1000 requests/day, sufficient for 200-sample eval).

3. Time: 8 weeks remaining.
   Mitigation: core pipeline already built; only real corpus + LLM + eval
   integration remains; Kaggle handles compute, no cluster provisioning needed.

4. Data: no access to real patient records (MIMIC gated access takes weeks).
   Mitigation: use epfl-llm/guidelines (public, 48K articles) + MedQA/PubMedQA
   (public benchmarks). This is explicitly noted in all publications in this space.

5. Safety/Ethics: prototype must not be mistaken for a clinical tool.
   Mitigation: hard-coded disclaimer in every API response and UI screen;
   escalation pathway to clinician for every low-confidence output.

   and Intelligent Systems on Human Well-Being) — guides the abstention mechanism
   design and the disclaimer requirements.

2. Reproducibility standards: all random seeds pinned in configs/seeds.yaml;
   library versions locked in requirements.txt; experiment configs version-controlled.

3. RAGAS evaluation framework: directly citable, standardized RAG evaluation —
   addresses the methodology-inconsistency gap identified in the literature review.

4. Data governance: all corpora are public guidelines or de-identified open-access
   datasets. No real patient-identifiable data is used at any stage.

5. Software engineering: PEP 8, type hints throughout, pytest coverage for all
   pipeline modules, GitHub Actions CI on every push.
